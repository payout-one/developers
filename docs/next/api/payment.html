Authentification

Bearer

For accessing the API a valid token must be passed in all the queries in the 'Authorization' header. A valid token is generated in Admin section of your account.

The following syntax must be used in the 'Authorization' header :

Code
Bearer <<token>>

So Authorization header can be like:

Code
Authorization: Bearer SFMyNTY.g3QAAAACZAAEZGF0YWEBZAAGc2lnbmVkbgYA6GI88F0B.4O2JwKmEX90ZfuSQMOuiVN-Vy_5FirRKp9JU2Pub

Create checkout

View as MarkdownSpec
/api/v1/checkouts

This request create checkout for payment where customer will authorize payment method for transaction.

To perform an idempotent request, provide an additional Idempotency-Key: header to the request. An idempotency key is a unique value generated by the client which the server uses to recognize subsequent retries of the same request. How you create unique keys is up to you, but we suggest using v4 UUIDs, or another random string with enough entropy to avoid collisions.

How to create the signature

Signature is created by few steps. First step is to create string concatenated with character | by joining arguments in following order:

  1. amount
  2. currency
  3. external_id
  4. nonce
  5. client_secret (obtained from merchant's API key)

After this step we should have string that looks like this: amount|currency|external_id|nonce|client_secret

Now, we use SHA256 hashing algorithm to hash this string and encode it using Base16. The signature is now complete and you can send it with the request.

Checkout statuses:

  • processing - created payment form
  • requires_capture - additional authorization requested (if some qate way has additional authorization)
  • successed - from checkout created transaction
  • expired - no transaction has been created. Expires 1 hour after creation

How to verify the signature

Signature is created by few steps. First step is to create string concatenated with character | by joining arguments in following order:

  1. amount
  2. currency
  3. external_id
  4. nonce
  5. client_secret (obtained from merchant's API key)

After this step we should have string that looks like this: amount|currency|external_id|nonce|client_secret

Now, we use SHA256 hashing algorithm to hash this string and encode it using Base16. The signature is now complete and you can send it with the request.

Checkout statuses:

  • processing - created payment form
  • requires_capture - additional authorization requested (if some qate way has additional authorization)
  • successed - from checkout created transaction
  • expired - no transaction has been created. Expires 1 hour after creation

Payment statuses:

  • pending - this status should not create because the payment card is verified online
  • successfull - confirmation from acquier that the transaction was successful
  • failed - confirmation from acquier that the transaction was failed
  • refunded - transaction refund ( automatically via API)

Bank stransfer statuses:

  • in_transit - created bank transfer
  • successfull - after reconciliation of the bank statement. (automatic matching)
  • refunded - transaction refund (manually via IS Payout)

Funds statuses:

  • pending - processed transaction, payment affecting pending balance
  • avaiable - processed transaction, payment affecting avaiable balance

Create withdrawal

View as MarkdownSpec
/api/v1/withdrawals

Creates a withdrawal with specified arguments.

To perform an idempotent request, provide an additional Idempotency-Key: <key> header to the request. An idempotency key is a unique value generated by the client which the server uses to recognize subsequent retries of the same request. How you create unique keys is up to you, but we suggest using v4 UUIDs, or another random string with enough entropy to avoid collisions.

How to create the signature

Signature is created by few steps. First step is to create string concatenated with character | by joining arguments in following order:

  1. amount
  2. currency
  3. external_id
  4. iban
  5. nonce
  6. client_secret (obtained from merchant's API key)

After this step we should have string that looks like this: amount|currency|external_id|iban|nonce|client_secret

Now, we use SHA256 hashing algorithm to hash this string and encode it using Base16. The signature is now complete and you can send it with the request.

Withdrawal statuses:

  • pending - manualy created withdrawal
  • in_transit - process withdrawal
  • paid - processed withdrawal

Request body

amount requiredstring
A positive number representing how much to charge in the smallest currency unit (e.g. 100 cents to withdraw 1.00€)
currency requiredstring
Three-letter [ISO currency code](https://www.iso.org/iso-4217-currency-codes.html), in uppercase.
external_id requiredstring
Identificator from your system.
iban requiredstring
IBAN of the bank account, where the amount will be sent.
customer requiredstring
Object containing customer's information.
statement_descriptorstring
Description that will appear on customer's statement
nonce requiredstring
Random alpha-numeric string, which will be used when creating `signature`. Max. 64 characters.
signature requiredstring
Hash containing vital information about the withdrawal, that will confirm authenticity of the request. Please refer to section below, if you want to know how to create this signature.

Retrieve withdrawal

View as MarkdownSpec
/api/v1/withdrawals/{withdrawal_id}

You can use this request to retrieve information about specified withdrawal.

How to verify the signature

Signature is created by few steps. First step is to create string concatenated with character | by joining arguments in following order:

  1. amount
  2. currency
  3. external_id
  4. iban
  5. nonce
  6. client_secret (obtained from merchant's API key)

After this step we should have string that looks like this: amount|currency|external_id|iban|nonce|client_secret

Now, we use SHA256 hashing algorithm to hash this string and encode it using Base16. The signature is now complete and you can send it with the request.

Withdrawal statuses:

  • pending - manualy created withdrawal
  • in_transit - process withdrawal
  • paid - processed withdrawal
