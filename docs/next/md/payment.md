## Create checkout

`POST /api/v1/checkouts`

This request create checkout for payment where customer will authorize payment method for transaction.

To perform an idempotent request, provide an additional Idempotency-Key: <key> header to the request. An idempotency key is a unique value generated by the client which the server uses to recognize subsequent retries of the same request. How you create unique keys is up to you, but we suggest using v4 UUIDs, or another random string with enough entropy to avoid collisions.

### How to create the `signature`

Signature is created by few steps. First step is to create string concatenated with character `|` by joining arguments in following order:

1. `amount`
2. `currency`
3. `external_id`
4. `nonce`
5. `client_secret` (obtained from merchant's API key)

After this step we should have string that looks like this: `amount|currency|external_id|nonce|client_secret`

Now, we use SHA256 hashing algorithm to hash this string and encode it using Base16. The signature is now complete and you can send it with the request.

### Checkout statuses:
* `processing` - created payment form
* `requires_capture` - additional authorization requested (if some qate way has additional authorization)
* `successed` - from checkout created transaction
* `expired` - no transaction has been created. Expires 1 hour after creation

### Request body

- `amount` — integer (required) · Amount in cents (integer) · e.g. 1050
- `currency` — string (required) · Currency code by [ISO 4217](https://en.wikipedia.org/wiki/ISO_4217) · e.g. EUR
- `customer` — object (required)
  - `first_name` — string (required) · Customer first name · e.g. John
  - `last_name` — string (required) · Customer surname · e.g. Doe
  - `email` — string (required) · Customer email · e.g. customer@payout.one

- `external_id` — string (required) · Client order's ID or another ID for reference to reason of payment. · e.g. f0ac316a-9ea6-7998-01a7-720437afb34c
- `idempotency_key` — string · Key uniq per request and user. It used for accepting request at most once. · e.g. 31f0ac6a-9ea6-01a7-7998-720437afb34c
- `metadata` — object · Can be used for payment notation or also for internal use, for example set origin of payment if merchant has more systems. · e.g. {'source': 'eshop'}
- `nonce` — string (required) · Required random data so signature cant be reused · e.g. ZUc0Mk9sVXZDOXNsdklzMQ
- `redirect_url` — string (required) · URL where user will be redirected after payment form is filled · e.g. https://redirect-url-example.payout.one/payment/redirect
- `signature` — string (required) · Request signature · e.g. 5a940ff7f1698f5d334527951519c84fa104c77ecf6691936093835bcac14d52

### Response

- `amount` — number · Amount in cents · e.g. 1050.0
- `currency` — string · Currency code by [ISO 4217](https://en.wikipedia.org/wiki/ISO_4217) · e.g. EUR
- `customer` — object
  - `first_name` — string (required) · Customer first name · e.g. John
  - `last_name` — string (required) · Customer surname · e.g. Doe
  - `email` — string (required) · Customer email · e.g. customer@payout.one

- `id` — number · Checkout ID · e.g. 1.0
- `external_id` — string · Client order's ID or another ID for reference to reason of payment. · e.g. f0ac316a-9ea6-7998-01a7-720437afb34c
- `idempotency_key` — string · Key uniq per request and user. It used for accepting request at most once. · e.g. 31f0ac6a-9ea6-01a7-7998-720437afb34c
- `metadata` — object · Can be used for payment notation or also for internal use, for example set origin of payment if merchant has more systems. · e.g. {"type: "eshop"}
- `nonce` — string · Required random data so signature cant be reused · e.g. ZUc0Mk9sVXZDOXNsdklzMQ
- `object` — string · Object type · e.g. checkout
- `redirect_url` — string · URL where user will be redirected after payment form is filled
- `signature` — string · Response signature · e.g. 5a940ff7f1698f5d334527951519c84fa104c77ecf6691936093835bcac14d52
- `status` — string · State of payment, for more information check States section · e.g. processing
- `checkout_url` — string · URL of payment form for users order. You should redirect user to this URL. · e.g. https://app.payout.one/checkouts/je81r4AasdJJdsdsdBMb9Go6mRglpwdax

### Example

```bash
curl -X POST https://app.payout.one/api/v1/checkouts \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
       "amount": "{{amount}}",
       "currency": "{{currency}}",
       "customer": {
         "first_name": "John",
         "last_name": "Doe",
         "email": "john.doe@payout.one"
       },
       "external_id": "{{external_id}}",
       "nonce": "{{nonce}}",
       "metadata": {
         "note": "Lorem Ipsum is simply dummy text of the printing and typesetting industry. Lorem Ipsum has been."
       },
       "redirect_url": "{{redirect_url}}",
       "signature": "{{signature}}"
     }'
```

## Create withdrawal

`POST /api/v1/withdrawals`

Creates a withdrawal with specified arguments.

To perform an idempotent request, provide an additional `Idempotency-Key: <key>` header to the request. 
An idempotency key is a unique value generated by the client which the server uses to recognize subsequent retries of the same request. How you create unique keys is up to you, but we suggest using v4 UUIDs, or another random string with enough entropy to avoid collisions.

### How to create the `signature`

Signature is created by few steps. First step is to create string concatenated with character `|` by joining arguments in following order:

1. `amount`
2. `currency`
3. `external_id`
4. `iban`
5. `nonce`
6. `client_secret` (obtained from merchant's API key)

After this step we should have string that looks like this: `amount|currency|external_id|iban|nonce|client_secret`

Now, we use SHA256 hashing algorithm to hash this string and encode it using Base16. The signature is now complete and you can send it with the request.

### Withdrawal statuses:
* `pending` - manualy created withdrawal
* `in_transit` - process withdrawal
* `paid` - processed withdrawal

### Request body

- `amount` — string (required) · A positive number representing how much to charge in the smallest currency unit (e.g. 100 cents to withdraw 1.00€)
- `currency` — string (required) · Three-letter [ISO currency code](https://www.iso.org/iso-4217-currency-codes.html), in uppercase.
- `external_id` — string (required) · Identificator from your system.
- `iban` — string (required) · IBAN of the bank account, where the amount will be sent.
- `customer` — string (required) · Object containing customer's information.
- `statement_descriptor` — string · Description that will appear on customer's statement
- `nonce` — string (required) · Random alpha-numeric string, which will be used when creating `signature`. Max. 64 characters.
- `signature` — string (required) · Hash containing vital information about the withdrawal, that will confirm authenticity of the request. Please refer to section below, if you want to know how to create this signature.

### Response

- `amount` — number · Amount in cents · e.g. 1050.0
- `api_key_id` — string · API key ID · e.g. 35a4cb08-2aa1-4482-90d9-2023c0255fb3
- `created_at` — number · Timestamp · e.g. 1556049039.0
- `currency` — string · Currency code by [ISO 4217](https://en.wikipedia.org/wiki/ISO_4217) · e.g. EUR
- `customer` — object
  - `first_name` — string (required) · Customer first name · e.g. John
  - `last_name` — string (required) · Customer surname · e.g. Doe
  - `email` — string (required) · Customer email · e.g. customer@payout.one

- `external_id` — string · Client order's ID or another ID for reference to reason of payment. · e.g. f0ac316a-9ea6-7998-01a7-720437afb34c
- `iban` — string · IBAN · e.g. SK01234567890
- `id` — number · Withdrawal ID · e.g. 1.0
- `nonce` — string · Required random data so signature cant be reused · e.g. ZUc0Mk9sVXZDOXNsdklzMQ
- `object` — string · Object type · e.g. withdrawal
- `signature` — string · Response signature · e.g. 5a940ff7f1698f5d334527951519c84fa104c
- `status` — string · State of payment, for more information check States section · e.g. pending

### Example

```bash
curl -X POST https://app.payout.one/api/v1/withdrawals \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
       "amount": "{{amount}}",
       "currency": "{{currency}}",
       "external_id": "{{merchant_id}}",
       "iban": "{{iban}}",
       "customer": {
         "first_name": "John1",
         "last_name": "Doe2",
         "email": "john.doe3@payout.one"
       },
       "signature": "{{signature}}",
       "nonce": "{{nonce}}",
       "statement_descriptor": "Simple statement description"
     }'
```
